Learn VALIS Workstation by doing

This tutorial teaches the full workflow from opening slides to validating registration quality and exporting outputs. It is designed for first-time users and lab handoff training.

What you will produce

One aligned OME-TIFF per slide in output/<project_name>/registered/ plus summary.csv with the quality metrics, created inside the application folder.

Time estimate

First run: 20-40 minutes including setup. Follow-up runs are usually 5-15 minutes depending on slide size.

Best entry setting

Keep the defaults: Align slides (rigid) ON, Fix tissue warping (non-rigid) ON, Working resolution 2048 px, feature detector VGG (Advanced Settings). Tune only if the quality check asks for it.

1. Goals and Outcomes

By the end of this tutorial, you should be able to:

  • load a folder of slides and check them in the Project and Slide Preview tabs;
  • run a rigid + non-rigid registration and understand what each Stage in the Status panel means;
  • judge the result with Blink, Analysis Plot and the Quality Report, and decide whether to accept or rerun;
  • use the post-registration tools: Export ROI Crop, Warp Annotations, Merge Slides, Save Options and Export Session Bundle;
  • tune Preferences and keep your settings reproducible with presets and saved configurations.

2. Choose a Track

Pick one path based on your immediate outcome. You can complete Track 1 first and then branch into Tracks 2-4.

Track 1 - Fast Path

  • Run with baseline defaults
  • Verify output folder + summary CSV
Go to Track 1
Track 2 - QA

Quality validation and triage

3. Preflight Checklist

Five minutes here saves a failed run later. Tick each row before you open the app.

Check Recommendation Reason
Python version 3.9+ Matches package requirement in pyproject.toml.
RAM 16 GB minimum, 32 GB preferred Large WSI tiles can spike memory usage.
Disk free space At least 10 GB free where the app lives; ideally 2-3x the total input size Below 10 GB the app refuses to start a run ("Insufficient disk space"). Below roughly 3x the input size it warns you first. Results are written to output/<project name>/ inside the application folder.
GPU (optional) CUDA + PyTorch CUDA build Speeds up the SuperPoint, DISK and DeDoDe detectors. Without it, Use GPU is greyed out and the app works fine on CPU.
Slide files Two or more files of type TIFF / OME-TIFF, SVS, NDPI, VSI, CZI, SCN, PNG or JPEG These are the extensions the folder scan recognises. Registration compares slides with each other, so a single slide cannot be registered.
Data prep: keep one case per folder. Only the files directly inside the folder you pick are loaded - sub-folders are not scanned - and they are listed alphabetically by file name.
Name your files in section order. If your files are called case7_HE.svs, case7_Ki67.svs and so on, the alphabetical order may not match the physical order of the sections. You can drag rows in the Project list to fix it later (section 6, step 3).

4. Install and Launch

Install in a virtual environment

git clone https://github.com/leonardolv/VALIS-GUI.git
cd VALIS-GUI
python -m venv .venv
.venv\Scripts\Activate.ps1      # Windows (PowerShell)
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
pip install -e .

Run the app

python run_valis_workstation.py

A splash screen reports what is loading (Java virtual machine, SimpleElastix check, user interface) and then the main window opens.

Quick health checks

python -c "import valis, napari; print('Core packages OK')"
python -c "import torch; print(torch.cuda.is_available())"
If the app launches but the viewer is missing: the centre of the window shows a Welcome page with a small note "Image viewer (napari) is not installed". Registration still works, but results cannot be previewed in the window and Tools -> Blink is unavailable. Install napari with pip install "napari[all]", then restart.

First launch only: the setup wizard

The very first time you start the app, a short VALIS Workstation Setup wizard appears. It has three pages:

  1. 1
    Welcome

    Summarises the four steps (Load, Configure, Register, Review). Click Next.

  2. 2
    Default Settings

    Choose a Default project name (results go in a folder with this name) and a Default output profile: WSI Archive (largest, for storage), Fast Review (smaller, quick to open) or Publication (high quality). Not sure? Keep the defaults - you can change both later in Properties.

  3. 3
    Done

    Leave Open Quick Tutorial when finished ticked if you want the 13-step in-app walkthrough, then click Finish. You can reopen it any time with F1.

6. First Registration (Hands-On)

Use the bundled example dataset to get a known-good first result. It contains five IHC serial sections:

examples/example_datasets/ihc/
    ihc_1.ome.tiff  ihc_2.ome.tiff  ihc_3.ome.tiff  ihc_4.ome.tiff  ihc_5.ome.tiff

Each step below says what to do, what you should see, and what to try if you do not.

  1. 1
    Open the slide folder

    Use any one of: the Open Slide Folder... button (Project tab, Quick Actions toolbar, or Welcome page), File -> Open Slide Folder / Ctrl+O, or drag the ihc folder onto the window. Pick examples/example_datasets/ihc.

    A loading overlay appears while thumbnails are generated. Then the tabs read Project (5) and Slide Preview (5), the status bar says "Loaded 5 slides from ihc", and the workflow strip moves to 2. Configure.

    If not: "No Slides Found" means the folder has no supported files directly inside it - pick the folder that contains the images, not its parent.

  2. 2
    Look at your slides

    Switch to the Slide Preview tab. Use the Size slider and the Grid / List buttons to judge that the tissue is visible and nothing is blank or corrupt.

    Five thumbnails. Hovering one shows its file details.
  3. 3
    Check the slide order

    In the Project tab slides are listed alphabetically. For the example that is already the correct order, so leave it. For your own data, if the files are not in physical section order, either drag rows into order and tick Slides already in order (Advanced Settings), or leave that box unticked and let VALIS sort them by similarity.

    No change needed for the example dataset.
  4. 4
    Confirm the settings

    In the Properties tab set Project name to IHC_Tutorial and leave everything else at its default:

    SettingValueWhat it does
    Align slides (rigid)onRotates, shifts and scales each slide so the tissue lines up roughly.
    Fix tissue warping (non-rigid)onThen bends each slide locally to correct deformation from sectioning. Greyed out, with a banner, if SimpleElastix is not installed.
    Working resolution2048 pxLongest side of the reduced copy used for aligning. Higher is more precise but slower.
    Use GPUoffOnly useful with the deep-learning detectors; greyed out without CUDA.

    Hover any setting for a plain-language tooltip. The two groups below (Advanced Settings (optional), Output Settings) stay collapsed until you tick their title box; you do not need them for this run.

    An empty name gets an orange border and a name with < > : " / \ | ? * gets a red one. (Invalid characters are replaced by _ when the run starts.)

    Tip: once you have settings you like, use the Presets row at the top of Properties: Save a named preset, Load it later, or Delete it.

  5. 5
    Run registration

    Press Ctrl+R (or File -> Run Registration, or the Run toolbar button). The app first checks the inputs, then shows Confirm Registration with the number of slides, input size, estimated output size and time, the output folder and every setting. Read it once, then click Yes.

    The strip moves to 3. Register and the Status panel starts counting.

    If not: Run Registration is greyed out until at least 2 slides are loaded (hover it for the reason). A "Validation Failed" box lists blocking problems, such as missing files, an output folder that is not writable, or less than 10 GB free. A "Validation Warnings" box lists soft problems (low space, very large slides) and asks whether to proceed.

  6. 6
    Watch the progress

    In the Status panel the Stage label walks through Starting, Preparing pipeline, Feature detection and rigid alignment, Warping and saving registered slides, Finalizing outputs and Complete. Elapsed and ETA update every second and the log scrolls (type in the filter box to search it).

    Progress reaches 100% and a "Registration complete." box appears.
    Cancelling: press Esc or the Cancel Registration button and answer Yes. Slides already written stay on disk; pending slides are not registered. File -> Resume Last Registration simply runs the same slides and settings again from the start.
  7. 7
    Review in the viewer

    The registered slides load into the canvas as layers named Registered: .... Open the Layers tab and untick/tick the visibility boxes or move the opacity sliders to flick between slides. The strip is now on 4. Review and the post-registration tools in the Tools menu are enabled.

    Tissue outlines stay put when you toggle layers. Go to section 7 for a proper quality check.
  8. 8
    Inspect outputs on disk

    Click Open output folder in the status bar, or browse to output/IHC_Tutorial inside the application folder.

    output/IHC_Tutorial/
    registered/     one aligned .ome.tiff per slide
    summary.csv     the quality metrics (same table as Tools -> Quality Report)
    transforms/     saved transforms for each slide
    overlaps/       before / after overlay pictures
    ...             other working folders written by VALIS
    You now have reproducible artifacts for QA and reporting. Use a new project name for each run so results are never mixed.

7. Quality Validation (Visual + Quantitative)

Use both overlays and metrics. Do not rely on one signal alone. All three tools below are in the Tools menu and are enabled once a run has finished.

Visual progression example

These are the overlap pictures VALIS writes for the IHC example: colour fringes along tissue edges show where the sections disagree.

A five-minute QA routine

  1. 1
    Blink the neighbouring pairs

    Open Tools -> Blink. Pick Slide A and Slide B (B starts on the second slide, so the two differ). Leave Mode on Blink, keep Interval at 600 ms (100-3000 ms) and click Start Blink. Watch a distinctive structure such as a vessel or a gland edge.

    A well-registered pair looks like the same picture changing colour, not shape. Anything that jumps sideways is residual misalignment. Click Stop Blink when done.

    The other modes: Swipe lets you move the Blend slider (0% = only Slide A, 50% = equal mix, 100% = only Slide B). Side-by-side shows both layers at full opacity and disables the slider; use the Layers tab to toggle them. Blink needs the napari viewer.

  2. 2
    Plot the error trend

    Open Tools -> Analysis Plot (window title Registration Analysis). It plots one error value per slide pair (x axis: Pair index). It uses the non-rigid rTRE column when there is one, otherwise the rigid one, and prints Metric | Mean | Max underneath.

    A flat line with no spikes. A single tall spike is a pair worth inspecting. Pairs with no measurement are excluded and counted in the label.
  3. 3
    Sort the Quality Report

    Open Tools -> Quality Report (Alignment Quality Report). Click a column header to sort, for example non_rigid_rTRE descending to see the worst pair first. Use Copy Table or Export CSV... for a spreadsheet, or right-click a row for Copy Row.

    ColumnMeaning
    from / toThe slide that was moved and the slide it was aligned to.
    original_*, rigid_*, non_rigid_*Error before registration, after the rigid stage, and after the non-rigid stage. The values should fall from left to right.
    *_DMedian distance between matched features (in physical_units).
    *_rTRETarget registration error, relative to image size, so pairs of different size can be compared. Lower is better.
    mean_*, *_time_minutesAverages across all pairs and the time each stage took.
    Every row improves from original to rigid to non_rigid. A row where it does not, or a row several times worse than its neighbours, is an outlier.
  4. 4
    Decide: accept or rerun one thing

    If the numbers and the Blink check agree the result is good, accept it. If one pair is bad, blink that pair at high zoom, then rerun changing one thing (for example a different Feature detector, or a higher Working resolution). Compare the new summary.csv with the old one.

Metrics view

Practical rule: if visual overlap is good but one pair has outlier error metrics, inspect that pair first in Blink before rerunning the full dataset.

Worked recipes

Recipe A - Export the same ROI from every slide

Goal: a 1024 x 1024 pixel region around a tumour edge, cut from all five registered IHC slides.

  1. 1
    Find the region

    In the viewer, hover the top-left corner of the region and read the cursor position in napari's status line. napari prints it as row, column - that is Y first, then X - so check with a known corner. Suppose the corner is at X = 2000, Y = 1500.

  2. 2
    Open the dialog

    Tools -> Export ROI Crop... and fill in X Coordinate 2000, Y Coordinate 1500, Width 1024, Height 1024 (the defaults are 0, 0, 1000, 1000). Set Format to OME-TIFF. Leave Reopen in Viewer ticked to check the result straight away.

    Handy buttons: Copy as JSON / Paste from JSON to share a box with a colleague, and Reset to return to the defaults.

  3. 3
    Choose a folder

    Click OK, then pick a destination in "Select Directory for ROI Crops". A progress box counts the slides.

    One file per slide named <slide>_ROI.ome.tiff, and a summary listing any slide that was clipped (the box ran past its edge), failed or was cancelled.

Recipe B - Transfer annotations to all slides

Goal: regions drawn once (for example in QuPath, saved as GeoJSON) appear on every other section.

  1. 1
    Prepare

    Export your annotations as tumour_regions.geojson from the slide you drew them on. Coordinates must be in pixels of that slide's original image.

  2. 2
    Run the tool

    Tools -> Warp Annotations. Click Browse next to Annotation file and pick the GeoJSON. Set Source slide to the slide the annotations were drawn on (not just any slide). Leave Output directory at its default, output/<project>/warped_annotations, or choose another. Click OK.

    One file per slide named <source>_to_<target>.geojson. The non-rigid warp is used whenever the run included non-rigid registration.
  3. 3
    Spot-check

    Load two or three of the outputs over the matching original slides in your annotation tool and confirm the outlines sit on the same tissue structures before using them in analysis.

Recipe C - Merge registered slides into one multi-channel image

Goal: three imaging rounds (say DAPI, CD3, CD8) combined into a single file for QuPath or Fiji.

  1. 1
    Open the dialog

    Tools -> Merge Slides... shows one row per registered slide (it needs at least 2).

  2. 2
    Fill the Channel Mapping table

    For each row: keep Include ticked (use Select All / Select None to flip them all), edit Channel Name (the default is Channel_1, Channel_2, ...; type DAPI, CD3, CD8), and pick a Color (Auto, Red, Green, Blue, Cyan, Magenta, Yellow, Gray, White). Each row contributes one named channel.

  3. 3
    Merge Options

    Output name: merged_image (the .ome.tiff ending is added). Normalize intensities: on by default - stretches each channel to a comparable range for display. Overlap handling only matters when two included slides share the same channel name (for example two rounds both called DAPI): Average, Maximum (brightest), Minimum (darkest), First or Last.

    Optional: Export config... saves the table as JSON for your records.

  4. 4
    Run it

    Click OK. The merge runs in the background (status bar: "Merging N channels..."). Compression, tile size and quality come from your current Output Settings.

    A "Merge Complete" box shows the path: output/<project>/merged_image.ome.tiff.

Recommended finalization sequence

  1. A
    Set output defaults before the production run

    Choose Compression, Tile size and Write image pyramid in Properties -> Output Settings (or an Output profile: WSI Archive, Fast Review, Publication). They are applied when the registered files are written, so changing them afterwards only affects later runs and merges.

  2. B
    Export ROI crops for focused review

    Use Tools -> Export ROI Crop... (recipe A) to generate aligned ROI subsets for rapid QC and animation workflows.

  3. C
    Package reproducibility artifacts

    Use File -> Save Configuration... and Tools -> Export Session Bundle... to create a settings file and a ZIP for collaborators, reviewers, or issue reports.

9. Settings Cookbook + VALIS Function Map

Scenario Recommended settings Why
Fast smoke test Working resolution 1024, non-rigid OFF Quick feedback on data quality and slide order.
Balanced production Working resolution 2048-4096, non-rigid ON, VGG Reliable quality without excessive runtime.
Challenging fluorescence DISK/SuperPoint + GPU, Use tissue masks ON, non-rigid ON Improves landmark robustness in difficult texture.
Highest precision Tick Fine-detail pass (micro-reg.), raise Working resolution and Fine-detail resolution Refines local alignment at higher resolution.

Decision Support Quick Matrix

If you see...Change firstThen verify with...
Good global overlap but local driftKeep Fix tissue warping (non-rigid) ON and test a higher Working resolutionBlink + outlier rows in Quality Report
Very long runtime on first passSet Working resolution to 1024 and temporarily untick non-rigidRuntime drop (see Elapsed in the Status panel) and basic rigid overlap quality
Fluorescence landmarks are inconsistentIn Advanced Settings switch Feature detector to DISK or SuperPoint, tick Use GPU if availableError trend in Analysis Plot and rTRE in Quality Report
Shear-like mismatch after rigid stageSet Rigid transform to Affine before changing many other parametersPairwise visual alignment in Blink
Memory pressure or stutterLower Working resolution, and in Preferences lower Max Thumbnail Cache and Parallel Thumbnail WorkersPerformance Statistics memory tab
Best practice: change one parameter group at a time, save each good state with File -> Save Configuration... (or a Properties preset) so you can roll back quickly.

10. Troubleshooting

Failure and Recovery Playbook

  1. 1
    Cancel or failure during run

    If the run failed, an Error Details box shows a plain-language message. Open Technical Details for the traceback and last log lines, then use Copy to Clipboard or Report Issue. To try again with the same slides and settings, choose File -> Resume Last Registration (it reruns from the start).

    You avoid re-entering all settings manually.
  2. 2
    Capture diagnostics

    Open Help -> Diagnostics and review runtime/environment state before rerunning. Copy to Clipboard puts the whole report on your clipboard.

    You can distinguish environment issues from parameter issues.
  3. 3
    Package evidence for support

    Run Tools -> Export Session Bundle... and save the current configuration with File -> Save Configuration....

    Issue reports include logs + reproducible settings.
  4. 4
    Recover from quality outliers

    Use Quality Report to identify worst pairs, inspect in Blink, then rerun with one controlled change.

    Faster convergence than full random retuning.

Common issues

What you see Why Action
Welcome page note "Image viewer (napari) is not installed"; Blink says "Napari not available." The optional viewer is missing. Install it: pip install "napari[all]", then restart. Registration works without it.
"No Slides Found" The folder has no supported files directly inside it. Pick the folder that holds the images (sub-folders are not scanned). Supported: TIFF, OME-TIFF, SVS, NDPI, VSI, CZI, SCN, PNG, JPEG.
Run Registration is greyed out Fewer than 2 slides are loaded, or a run is already active. Load a folder with 2+ slides. Hover the action for the exact reason.
Banner "SimpleElastix not found. Only Rigid Registration is available." and the non-rigid box is greyed SimpleITK with Elastix is not installed. Work with rigid only, or install SimpleElastix and restart.
GPU checkbox disabled No CUDA-enabled PyTorch. Install a CUDA-capable PyTorch build and verify torch.cuda.is_available().
"Validation Failed: Insufficient disk space" Less than 10 GB free on the output drive. Free space or move the application folder to a larger drive.
Registration too slow Large working resolution, non-rigid or micro-registration on. Lower Working resolution (1024), turn off non-rigid for test runs, use ORB/BRISK for speed checks.
Out of memory Slides or working resolution too large for RAM. Lower Working resolution, close other memory-heavy apps, register fewer slides at a time, check Help -> Performance Statistics -> Memory.
Tools -> Blink / Merge etc. are greyed out No finished run in this session. Run a registration first; the tools unlock when it completes.
Log file: detailed diagnostics are written to logs/valis_workstation.log in the application folder, and the same lines appear live in the Status panel.
