1 — What Is VALIS?

VALIS (Virtual Alignment of pathoLogy Image Series) is a Python library for registering (aligning) serial whole-slide images. It was published in Nature Communications and handles brightfield (H&E, IHC) and fluorescence (CyCIF, CODEX, mIHC) images.

VALIS Workstation is the graphical desktop application that wraps VALIS in a user-friendly GUI — no command-line or programming knowledge required.

What can it do?

  • Align 2 or more tissue slides (serial sections, restained, multiplexed)
  • Correct both linear (rotation, scale) and non-linear (elastic) tissue deformations
  • Export registered images as pyramidal OME-TIFF (compatible with QuPath, OMERO, ImageJ)
  • Merge registered slides into multi-channel composites
  • Transfer annotations (GeoJSON) between registered slides
  • Measure registration quality with built-in error metrics

2 — Key Concepts (Before You Start)

Understanding these five terms will make everything else clearer:

TermPlain-English Explanation
RegistrationThe process of aligning two or more images so that the same tissue structures overlap. Think of it as "stacking" slides on top of each other.
Rigid registrationCorrects rotation, scaling, and translation. The tissue shape stays unchanged — only its position and angle are fixed.
Non-rigid registrationCorrects elastic deformations (stretching, folding, tearing). The tissue shape is gently warped to match its pair.
Feature detectionAutomatically finding unique "landmarks" (keypoints) in each image — like corners, edges, or texture patterns — that can be matched across slides.
OME-TIFFAn open standard image format for microscopy. Supports multiple resolution levels (pyramids), tiling, and rich metadata. Compatible with QuPath, OMERO, ImageJ/FIJI, Napari.

3 — Installation

Prerequisites

  • Python 3.9+ (3.13 tested)
  • pip or conda
  • Git
  • CUDA toolkit (optional — for GPU-accelerated deep-learning detectors)

Option A — pip (simplest)

git clone https://github.com/leonardolv/VALIS-GUI.git
cd VALIS-GUI
python -m venv .venv
.venv\Scripts\Activate.ps1          # Windows
# source .venv/bin/activate         # macOS/Linux
pip install -r requirements.txt
pip install -e .

Option B — conda (recommended for GPU)

conda create -n valis-gui python=3.10 -y
conda activate valis-gui
conda install numba llvmlite -c conda-forge
pip install -r requirements.txt && pip install -e .

Verify installation

python -c "import valis; import napari; from PySide6 import QtWidgets; print('All OK')"
Tip: If Napari is missing: pip install napari[all]

4 — Your First Registration (Step by Step)

Complete your first registration in under 5 minutes:

1
Launch the application 
python run_valis_workstation.py
2
Open a slide folder — File → Open Slide Folder (Ctrl+O) or drag a folder onto the window.
3
Review your slides — Thumbnails appear in the Slide Preview panel. Hover over each for metadata.
4
Check settings — The Properties panel on the right shows all options. For beginners, the defaults are excellent:
  • Feature Detector: VGG (works on all tissue types)
  • Rigid + Non-rigid: both enabled
  • Max image size: 2048 px
5
Run registration — Press Ctrl+R. Review the confirmation dialog, then click Start Registration.
6
Monitor progress — Watch the progress bar and logs in the Status panel. You can cancel anytime.
7
Explore results — Registered slides load into the Napari viewer. Toggle visibility, opacity, and colormaps in the Layers panel.
8
Check quality — Use Tools → Quality Report to see error metrics, or Tools → Blink for visual comparison.

What good registration should look like

Practical check: if edges are still visibly doubled in key tissue regions, rerun with higher max image size or enable micro-registration.

9 — Common Use Cases

🔬 Serial H&E Sections

Brightfield

Scenario: You have 5–20 serial sections stained with H&E and need to align them for 3D reconstruction or cross-section comparison.

Settings: Feature detector = VGG · Transform = Similarity · Non-rigid = ON

Tips: Default settings work well. Enable "Slides pre-ordered" if your slides are already in physical order.

🧬 CyCIF / CODEX Multiplexed Imaging

FluorescenceMultiplex

Scenario: Multiple rounds of staining on the same slide. Each round has DAPI + 2–4 markers. You need to align rounds and merge into one multi-channel image.

Settings: Feature detector = DISK or SuperPoint · Transform = Similarity · Non-rigid = ON

After registration: Use Tools → Merge Slides to create the composite. Name channels (DAPI, CD3, CD8, PanCK, etc.) and assign colors.

🎯 IHC Serial Stain Comparison

Brightfield

Scenario: Adjacent sections with different IHC stains (e.g., Ki67 vs. p53). Register to compare marker expression in the same tissue region.

Settings: Feature detector = VGG · Tissue masks = ON · Crop = all_overlap

After registration: Use Tools → Blink to visually toggle between stains at the same location.

📐 Annotation Transfer

BrightfieldFluorescence

Scenario: A pathologist drew regions of interest on one slide (e.g., tumor boundary). You need those annotations on all other registered slides.

After registration: Use Tools → Warp Annotations. Select the GeoJSON file, choose the source slide, and one warped file is created per target.

10 — Frequently Asked Questions

Q: What image formats are supported?

TIFF, OME-TIFF, SVS (Aperio), NDPI (Hamamatsu), MRXS (3DHISTECH), CZI (Zeiss), LIF (Leica), ND2 (Nikon), JPEG, PNG, BMP, and 300+ more via Bio-Formats.

Q: Is there a step-by-step tutorial for new lab members?

Yes. Open VALIS-GUI-Tutorial.html for a didactic, image-guided workflow from setup through quality validation.

Q: My GPU checkbox is grayed out — why?

PyTorch was not installed with CUDA support, or no CUDA GPU was detected. Install PyTorch with CUDA: pip install torch --index-url https://download.pytorch.org/whl/cu121

Q: Which feature detector should I use?

VGG is the best default for most cases. For fluorescence images, try DISK or SuperPoint. For maximum speed, use ORB or BRISK.

Q: Registration is very slow — how to speed it up?

Reduce Max image size (try 1024). Disable Non-rigid registration for initial tests. Use a classical detector (VGG, BRISK, ORB) instead of neural.

Q: Can I cancel a running registration?

Yes. Click Cancel in the Status dock. Partial output may remain.

Q: What is the output?

Pyramidal OME-TIFF files + a CSV summary with alignment metrics. Configure via Tools → Save Options.

Q: Does this work on macOS / Linux?

Yes. PySide6 + Napari are fully cross-platform.

Feature Detectors — Choosing the Right One

VALIS supports 8 feature detectors spanning classical computer vision and modern deep learning. The detector you choose affects speed, accuracy, and GPU requirements.

DetectorTypeGPUSpeedAccuracyBest For
VGGClassicalNo⚡⚡⚡⭐⭐⭐⭐General-purpose default. BRISK detector + VGG descriptor.
KAZEClassicalNo⚡⚡⭐⭐⭐⭐Scale-space features, robust to blur and noise.
BRISKClassicalNo⚡⚡⚡⚡⭐⭐⭐Fast binary descriptor, real-time processing.
ORBClassicalNo⚡⚡⚡⚡⚡⭐⭐Fastest option, rotation-invariant, low memory.
AKAZEClassicalNo⚡⚡⚡⭐⭐⭐⭐Accelerated KAZE, balanced speed/quality.
SuperPointNeuralYes*⚡⭐⭐⭐⭐⭐Highest accuracy for challenging tissue.
DISKNeuralYes*⚡⚡⭐⭐⭐⭐⭐Dense features, used in default VALIS pipeline with LightGlue.
DeDoDeNeuralYes*⚡⭐⭐⭐⭐⭐State-of-the-art descriptor-free detection.

* GPU strongly recommended. Will run on CPU but 10–50× slower.

Default pipeline: VALIS uses VGG for initial sorting, then DiskFD + LightGlueMatcher for the actual registration matching. The GUI's "Feature detector" setting controls the sorting matcher.

Beyond these 8, the VALIS library also supports: DaisyFD, LatchFD, BoostFD, OrbVggFD, SKOrbVggFD, CensureVggFD (programmatic use only).

Feature Matchers

After detecting features, VALIS matches corresponding keypoints between pairs of images. Three matcher types are available:

MatcherDefault DetectorMethodNotes
Matcher (traditional)VggFDDescriptor distance + USAC_MAGSAC filteringGood with any classical detector
SuperGlueMatcherSuperPointFDSuperGlue neural graph matchingBest with SuperPoint features
LightGlueMatcherDiskFDKornia LightGlue matchingDefault in VALIS pipeline. Brute-force rotation estimation.

Outlier filtering methods: USAC_MAGSAC (default), RANSAC, GMS (Grid-based Motion Statistics), Tukey fences.

Optimization Tips

Speed optimization

  • Reduce Max image size to 1024 for quick tests
  • Disable non-rigid registration for initial alignment inspection
  • Use ORB or BRISK detector (fastest classical)
  • Enable Slides pre-ordered if you know the physical order — skips the sorting step entirely
  • Set lower Pyramid levels (2 instead of 4)

Quality optimization

  • Increase Max image size to 4096 or higher
  • Use DISK or SuperPoint with GPU enabled
  • Enable Micro-registration for sub-pixel accuracy
  • Enable Tissue masks to focus matching on tissue regions only
  • Enable Denoise for noisy fluorescence images

Memory optimization

  • Lower max image size and pyramid levels
  • Reduce tile cache in Preferences → Cache
  • Monitor memory via Help → Performance Statistics

Decision Trees — Choosing Settings

🌳 Which feature detector should I use?

❓
Is this your first time using VALIS?
✅
Yes → Use VGG (default). Works well for almost all tissue types.
❓
Do you have a CUDA GPU and need maximum accuracy?
✅
Yes → Use DISK (best balance) or SuperPoint (highest accuracy but slower).
❓
Do you need maximum speed (e.g., hundreds of slides)?
✅
Yes → Use ORB (fastest) or BRISK (fast with better quality).
❓
Are your images blurry or low-quality?
✅
Yes → Use KAZE (scale-space features, robust to blur).

🌳 Which transform model?

❓
Are your tissue sections cut at different thicknesses or show size variation?
✅
Yes → Use Similarity (default). Corrects rotation + scaling + translation.
❓
Is there shearing from mounting?
✅
Yes → Use Affine. Adds shear and non-uniform scaling.
❓
Are sizes consistent and only orientation varies?
✅
Yes → Use Rigid/Euclidean. Rotation + translation only, preserves scale.

🌳 Which crop mode?

📐
reference (default) — Crop output to the reference slide's boundary. Best for most cases.
🔲
all_overlap — Only keep the region where ALL slides overlap. Useful for analysis requiring complete correspondence.
📏
all — Expand to include the union of all slides (may have blank borders).
↔️
unchanged — No cropping at all.

Failure and Recovery Playbooks

These playbooks are optimized for minimum downtime and reproducible issue reporting.

1) Registration canceled intentionally

Use File -> Resume Last Registration, confirm settings, and rerun. Partial outputs may remain, so compare timestamps in the output folder before reusing files.

2) Registration failed with error dialog

Copy technical details, open Help -> Diagnostics, then export a session bundle from Tools -> Export Session Bundle... for support triage.

3) Unexpected close or crash

Reopen the app, reload your slide folder, then use Load Configuration if available. Resume from the last known-good run context and verify summary.csv.

4) Out-of-memory or severe slowdown

Lower max image size and pyramid levels, reduce cache limits in Preferences, rerun with non-rigid OFF for triage, then re-enable once baseline rigid alignment looks good.

5) Quality outliers after success

Open Quality Report, locate worst pairs, inspect them in Blink, then rerun with one controlled change (detector or transform) rather than a full parameter reset.

6) Escalation package for maintainers

Attach the exported session bundle, your configuration JSON, and exact reproduction steps. This provides a high-signal issue report with logs and runtime context.

Known Limits and Pending Features

Status snapshot aligned to repository docs as of 2026-04-11. See README roadmap and workstation changelog for updates.

Batch project processing

Single-project interactive flow is primary today. Batch mode remains under consideration in roadmap planning.

Core dialogs are integrated, but a formal plugin API/system is listed as future work.

All Dialogs & Tools (Complete Reference)

🔄 Blink Viewer ▶

Purpose: A/B comparison of registered slides.

  • Slide A / B: ComboBox selectors for any two registered slides
  • Blend slider: Manual crossfade 0–100%
  • Blink mode: Timer-driven toggle at 600ms intervals
Tip: Blink first to spot gross errors, then blend for fine assessment.
📈 Analysis Plot ▶

Purpose: Matplotlib chart of Target Registration Error (TRE) per slide pair.

  • Line/bar plot with markers showing error per pair
  • Summary label: Mean / Max error
  • Matplotlib toolbar: zoom, pan, save as PNG
📋 Quality Report ▶

Purpose: Sortable data table of all alignment quality metrics.

Columns: Slide name, Rigid error, Non-rigid error, Features matched. Click headers to sort.

Data source: summary_df which includes: rigid_D, rigid_rTRE, non_rigid_D, non_rigid_rTRE, rigid_time_minutes, non_rigid_time_minutes

📎 Warp Annotations ▶

Purpose: Transfer GeoJSON annotations from one slide's coordinate system to all others.

  1. Browse for a .geojson file
  2. Select the source slide (the one annotations were drawn on)
  3. Choose output directory (default: <output>/warped_annotations/)
  4. Click OK — one warped GeoJSON per target slide

"Napari not available"

pip install napari[all]

GPU checkbox disabled

pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

"SimpleElastix not found"

Without SimpleElastix, only rigid registration works. Non-rigid uses OpticalFlowWarper as an alternative.

Out of memory

  • Reduce Max image size and Pyramid levels
  • Lower tile cache in Preferences
  • Monitor via Help → Performance Statistics → Memory tab

Wheel build errors

conda install numba llvmlite scikit-image -c conda-forge

Example: Warp points between slides

import numpy as np

# Get slide objects
slide_a = registrar.get_slide("slide_001.tiff")
slide_b = registrar.get_slide("slide_002.tiff")

# Points in slide_a's coordinate system
points = np.array([[100, 200], [300, 400], [500, 600]])

# Warp to slide_b's coordinate system
warped_points = slide_a.warp_xy_from_to(points, slide_b)
print(warped_points)

Glossary

Registration
The process of aligning two or more images so corresponding structures overlap.
Rigid registration
Alignment using only rotation, scaling, and translation. Shape is preserved.
Non-rigid / elastic registration
Alignment that allows local deformation (stretching, warping) of the tissue.
Feature detection
Automatic identification of distinctive landmarks (keypoints) in images.
Feature matching
Finding corresponding keypoints between two images.
TRE (Target Registration Error)
The distance between corresponding points after registration. Lower = better.
rTRE (relative TRE)
TRE normalized by image size for cross-study comparison.
OME-TIFF
Open Microscopy Environment TIFF — a standardized format for microscopy images.
Pyramid / multi-resolution
An image stored at multiple resolutions for efficient viewing at different zoom levels.
Displacement field
A 2D grid of (dx, dy) vectors describing how each pixel should move during non-rigid warp.
Optical flow
A computer vision technique estimating pixel-level motion between frames.
Affine transform
A linear transformation including rotation, scaling, shearing, and translation.
Similarity transform
A subset of affine: rotation + uniform scaling + translation.
Brightfield microscopy
Standard transmitted-light microscopy (H&E, IHC stains).
Fluorescence microscopy
Imaging using fluorescent markers excited by specific wavelengths.
CyCIF
Cyclic Immunofluorescence — iterative staining and imaging of the same tissue.
CODEX
CO-Detection by indEXing — highly multiplexed tissue imaging.
GeoJSON
A JSON-based format for encoding geographic/spatial data. Used for slide annotations.
Bio-Formats
A Java library for reading 300+ microscopy file formats.
pyvips
Python bindings for libvips, a fast image processing library efficient with large images.
SimpleElastix
A medical image registration library built on SimpleITK, providing B-spline deformation.
USAC_MAGSAC
A robust outlier rejection method for geometric model estimation.
LightGlue
A lightweight neural feature matcher from Kornia.
DISK
A learned local feature detector and descriptor.
SuperPoint
A self-supervised deep learning keypoint detector and descriptor.
